# BNB → USDT 首次报价三层往返实测

基线为 PR #3 上轮提交 `d9fd9ba00a7c4ded370db34bb8f28e59320fd3ae`。以相同真实区块对照 **0.001 BNB→USDT**，滑点 0.5%，多跳开启。候选版本把三层金额报价的三次 HTTP 合为一次，仍在收到结果后发起独立的最终区块 hash 核对。预热后首次输入中位数 **2,585.66 → 729.11 毫秒**，三组中的两组低于 1 秒。冷启动中位数 **7,304.95 → 3,734.09 毫秒**。

## 实现和边界

仅服务端、当前验证过的 FstSwap 2.1 主网部署、BNB→USDT 多跳报价适用。路由枚举、池准入和转账税模型读取照常执行。所有参与路径的代币只有通过现有零税模型检查才可能使用模拟，并且 helper 的代币和 adapter 受固定主流地址限制。浏览器回退和其他币对继续沿用原路径。

一次固定区块的只读 `eth_call` 执行 constructor，将上一层实际输出作为同一路线的下一层输入。constructor 继续按原顺序调用 Multicall3，router 和 adapter 看到的调用者保持一致，按原 adapter、path 和 amount 去重。首层直接池拆分仍由原 JS 按整数比例及余数计算。模拟不发送交易，也不持久部署任何合约。

对错误区块、缺项、零输出、重复 key 输出不一致、无效响应或必要子调用失败，整组模拟结果不能进入报价缓存，按原分层方式重新读取。每次模拟声明的 Gas 上限为 1,200 万，仅用于限制只读节点计算，没有 Gas 支出。单次可选请求最多等 1.5 秒，同节点无效响应或失败后短期跳过模拟。节点限流和请求取消沿原语义传播。候选数量、输入体积、调用批次和返回体积均有限制，超出就用既有路径，无需删减候选。

候选排序、价格影响、手续费、各阶段及全局最低到账仍由原 JS 计算。固定区块、节点绑定、canonical 顺序和原报价期限均保留，页面 CSS、转账税模型和兑换部署合约源码未改。独立复核通过。

## 公网同区块配对

本地引擎连接 PublicNode BSC RPC，三组分别固定到真实区块 `0x80b35ad`、`0x80b35e0`、`0x80b360d`。每组交替版本顺序。冷指新引擎和新 provider pool，TCP、DNS 和 ABI 可能已热。两侧新建引擎单独完成 BNB→USDT 池状态预热后，再输入首个金额。预热成本记录在表内，没有合入该行首报耗时。浏览器端到端时间未测。

| 场景 | 第 1 组基线 → 候选 ms | 第 2 组基线 → 候选 ms | 第 3 组基线 → 候选 ms | 中位数 ms | HTTP |
|---|---:|---:|---:|---:|---:|
| 冷报价 | 7,304.95 → 2,926.81 | 5,846.08 → 3,734.09 | 7,541.27 → 5,227.46 | 7,304.95 → **3,734.09** | 14 → 12 |
| 单币对预热 | 3,528.99 → 6,688.70 | 4,068.21 → 2,751.64 | 4,399.09 → 5,400.43 | 4,068.21 → 5,400.43 | 12 → 12 |
| 预热后首报 | 1,541.59 → **726.14** | 2,585.66 → **729.11** | 6,019.13 → 2,696.41 | 2,585.66 → **729.11** | 4 → 2 |

六次候选报价均成功命中模拟，没有触发回退。每次金额阶段由原来三个依赖层的 19、27、20 个子调用，变为一次 HTTP 里执行同一组 **66 个唯一报价**。生产报价仍收到 119 个计划步骤的结果，其中包括重复量和拆分量。工具按目标、calldata 和前一层真实输出逐项重建并对照 **396 项**原始金额结果，无缺失、额外或不同。最终有 **18/18 有效操作**。六组报价的区块、净到账、最低到账、手续费、选中路线与 51 个候选的计数均一致。真实剩余有效期最小为 7,251 毫秒。

模拟的六次公网传输所在窗口约 **363–406 ms**。预热后的慢样本 2,696.41 ms 中，模拟阶段随 JS 处理用了约 439 ms，最终区块核对用了 **2,256 ms**。冷报价仍需读取配置、Oracle、V2 和 V3 池状态及深度，三组均未达到 1 秒。单币对预热逻辑没有纳入这一捷径，预热时间样本中也有变慢。样本量为三组，不能据此承诺稳定小于 1 秒或推断线上尾延迟。

## 验证和复现

- `npm test` 945/945 通过。固定 solc 0.8.26 的字节码复现校验通过，独立本地 EVM 38/38 通过。EVM 覆盖三层按调用者和 calldata 逐项差分、精确大整数、混合 V2/V3、越界和失败边界，新增服务回归覆盖取消、报价返回前的最终区块核对、税模型和限流。
- `npm run build:check`、修改的 MJS 语法检查、`git diff --check` 通过。生成运行时使用原页面样式。
- 前置能力检查的两个公网节点都支持该形式的只读 `eth_call`。固定回包测试和 50,000 Gas 的预期失败都保留。低成本能力探测不能代替真实负载测量，也不证明节点的有效执行 Gas 上限。单独的预热试跑也保留，只用正式配对报告对比中位数。
- 本轮更新了 PR，未部署。
